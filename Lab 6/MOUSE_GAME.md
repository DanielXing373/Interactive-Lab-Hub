# Lab 6 三人合作捕鼠街机

四人小组负责开发与联调。游戏由三人同屏操作，每人负责瞄准、攻击或控灯中的一项。全队共享单局分数，每局独立结算并进入分数板。

## 操作与设备

| 角色 | 设备与出处 | 操作 |
| --- | --- | --- |
| 瞄准 | Pi 1 + SparkFun Qwiic Joystick。见 Lab 4 的 [Joystick 小节](../Lab%204/README.md#joystick)和[摇杆测试脚本](../Lab%204/joystick_test.py)。 | 推动摇杆，准星沿对应方向移动一格。摇杆回中后可再次移动。启动时校准中心、死区和轴方向。 |
| 攻击 | Pi 2 + Patroller 使用过的 Qwiic/I²C 距离传感器。见 Lab 4 的 [The Patroller 项目记录](../Lab%204/README.md#lab-overview)、[Distance Sensor 小节](../Lab%204/README.md#distance-sensor)和 [VCNL4040 测试脚本](../Lab%204/distance_sensor_test.py)。 | 手靠近触发一次挥锤，移开后才能再打。根据实测读数设置不同的触发和复位阈值。VCNL4040 返回接近计数，实物型号以板上标记为准。 |
| 控灯 | Pi 3 + USB 摄像头。复用 Lab 4 的[摄像头测试脚本](../Lab%204/camera_test.py)中的 OpenCV 取图路径，用 [MediaPipe Pi 示例](https://github.com/google-ai-edge/mediapipe-samples/blob/main/examples/gesture_recognizer/raspberry_pi/recognize.py)识别手势。 | 张掌开灯，握拳关灯。稳定识别后才切换，手放下或离开画面时保持当前灯态。画面内的灯光与摄像头所在环境的照明独立。 |

## 游戏规则

- **开局**。共享画面显示 3×3 个鼠洞、准星、倒计时、分数、剩余奶酪和灯的状态。每局最多 60 秒，初始 5 块奶酪、0 分、亮灯、晕眩可用。每个洞同时最多容纳一只鼠。
- **刷鼠**。亮灯少刷，暗灯多刷。灯态只决定新鼠出现的频率，晕眩按下文的规则处理场上已有的鼠。
- **出场与偷窃**。老鼠出现后留在原洞，先馋奶酪并显示长读条。长读条结束时瞬间抱起一块奶酪，换成明显的抱奶酪姿势，再进入带短读条的撤退阶段。撤退中的鼠仍可在原洞命中。短读条走完后老鼠离场并扣一块奶酪。
- **命中**。挥锤时按当前准星所在的洞判定。命中移除该鼠并加 1 分，即使它已抱住奶酪也不会扣除。打空只播放挥锤反馈。奶酪在老鼠成功离场时才扣除。
- **全屏晕眩**。技能就绪时，从暗切到亮触发一次全屏亮起和老鼠头顶的惊叹号。暂停刷鼠和场上老鼠的读条，准星、攻击和全局倒计时继续。晕眩结束时，所有仍在场的晕眩鼠直接消失。空手鼠消失不扣奶酪，每只抱着奶酪的鼠消失时带走一块。消失本身不加分。
- **冷却**。从晕眩触发时开始计时。冷却期间仍可开关灯并改变刷鼠频率。保持亮灯、重复张掌或冷却自然结束都不会触发晕眩。画面显示技能是否就绪和剩余冷却。
- **结算**。全局倒计时归零或奶酪清空即结束。停止本局的刷鼠、输入判定和计分，每局只写入一条成绩。分数板显示抓鼠数、剩余奶酪和存活时间，按抓鼠数排序，同分依次比较剩余奶酪和存活时间。成绩保存在游戏主机上。由玩家手动开新局并自行决定角色。

### 首轮调参

| 参数 | 起始值 |
| --- | --- |
| 亮灯 / 暗灯刷鼠间隔 | 2.8 秒 / 1.0 秒 |
| 馋奶酪 / 撤退读条 | 1.6 秒 / 0.6 秒 |
| 晕眩时长 / 冷却 | 1.2 秒 / 6 秒 |

试玩时对比同一组全亮、全暗和主动切灯的表现。暗灯应提供更多得分机会，同时增加漏鼠风险。若全暗更容易拿高分，优先调快暗灯刷鼠，或缩短读条以提高开灯救场的价值。

## 架构与小组分工

三台 Pi 各自读取并处理输入，通过课程 MQTT broker 发送动作。笔记本统一管理游戏状态、计分和分数板，再通过 Flask / Socket.IO 更新共享浏览器画面。摄像头图像在 Pi 上处理，MQTT 只传控灯状态。通信结构参考 Lab 6 的 [作业说明](README.md)、[游戏主机可复用的服务端示例](app.py)和 [Pi 发布示例](pixel_grid_publisher.py)。

| 负责人 | 模块 | 接口 |
| --- | --- | --- |
| 组员 1 | 摇杆、中心和方向校准 | `IDD/<team>/mouse-game/aim`，发布上、下、左、右的单步移动事件 |
| 组员 2 | 距离传感器、触发和复位校准 | `IDD/<team>/mouse-game/attack`，每次挥锤发布一个事件 |
| 组员 3 | USB 取图、手势稳定识别 | `IDD/<team>/mouse-game/light`，发布明确的亮或暗状态 |
| 组员 4 | 游戏逻辑、共享画面和分数板 | 订阅三路输入，维护局内状态并负责整合 |

动作消息不使用 MQTT retain，避免订阅或重连时把旧动作当成当前操作。开局清空待处理动作，结算后忽略局内输入。

## 开发指南

1. **验收硬件与通信。** 三台 Pi 分别跑通传感器测试。测量摇杆中心、距离触发范围、张掌与握拳的稳定性。随后从每台 Pi 发测试消息，确认笔记本能订阅三路主题。
2. **跑通一局。** 先用键盘模拟三种输入，完成九宫格、老鼠阶段、灯光晕眩、命中、两种结束条件、分数板和手动重开。
3. **接入实物并联调。** 逐路换成 MQTT 输入，重点检查回中才能再移动、手悬停只打一次、持续张掌只开一次灯。验证晕眩结束时空手鼠与抱奶酪鼠分别结算，以及奶酪归零后只写入一条成绩。
4. **试玩与记录。** 邀请至少两位非组员试玩，记录他们对操作的预期、意外之处和改进建议。对比不同用灯策略，调整刷鼠与读条参数。保存三套 Pi 接线照片、试玩照片或视频，并在最终提交 README 中加入架构图、MQTT 主题、代码说明和反思。Part B 另保留像素网格截图与 Pi 设置照片。
